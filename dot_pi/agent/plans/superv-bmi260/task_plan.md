# Plan: Enable the BMI260 accelerometer on the OneXPlayer Super V

## Verified background

- The sensor is a **Bosch BMI260** (6-axis accel+gyro) on **I2C bus i2c-1 @ 0x68**, chip id `0x27`.
- The correct kernel driver **`bmi270`** (with BMI260 support + `bmi260-init-data.fw`) exists in all installed kernels (7.1.5, 7.2.0-rc5, 6.18.40-LTS); firmware blob is in `/lib/firmware/`.
- **OEM firmware bug**: the DSDT declares the sensor with `_HID "10EC5280"` (a Realtek ID) instead of `BMI0260`. So the `bmi160` driver grabs the node via its `10EC5280` quirk and fails (chip id mismatch), while `bmi270` never gets a match. Runtime workarounds (delete/new_device/driver_override) are all blocked by kernel design.
- The chip is currently **latched in an init-error state** (`internal_status = 0x02`) after my earlier test — only a **power cycle (reboot)** clears it. The reboot below doubles as the power cycle.
- A boot-time NAK was observed once (`-121`); a retry mechanism (step 7) guards against the sensor rail coming up late.

## Steps

- [x] **1. Install ACPI tooling** — `pkexec pacman -S --noconfirm acpica` (iasl) ✅
      *Dependencies:* none
      *Files:* n/a (package install)
      *Rollback:* `pacman -R acpica`

- [x] **2. Dump & decompile DSDT** — sensor found in **SSDT26** (`I2C1.SPBA`, `_HID 10EC5280`, `_CRS → 0x68` on `\_SB.PC00.I2C1`, `ROMS` matrix `0 1 0 / 1 0 0 / 0 0 -1`) ✅
      *Dependencies:* step 1
      *Files:* /tmp/dsdt.dat, /tmp/ssdt/SSDT26.dsl (create)
      *Rollback:* none (read-only)

- [x] **3. Patch & recompile** — `_HID` + `_CID` `10EC5280 → BMI0260`, oem_revision `0x1000 → 0x1001`; `iasl -f -tc` → SSDT26.aml (header verified, round-trip clean) ✅
      *Dependencies:* step 2
      *Files:* /tmp/ssdt/SSDT26.dsl (edit), /tmp/ssdt/SSDT26.aml (create)
      *Rollback:* keep original dump; no system change yet

- [x] **4. Install ACPI override + rebuild initrd** — SSDT26.aml → `/etc/initcpio/acpi_override/`; `acpi_override` hook added to `HOOKS`; rebuilt via the canonical `limine-mkinitcpio-install` script (all 3 kernels); limine.conf hashes refreshed; verified `SSDT26.aml` inside each initramfs ✅
      *Note:* CachyOS uses **Limine + kernel-install machine-id layout** (not plain mkinitcpio -P); initramfs lives at `/boot/<machine-id>/<kernel-id>/initramfs`
      *Dependencies:* step 3
      *Files:* /etc/initcpio/acpi_override/SSDT26.aml (create), /etc/mkinitcpio.conf (edit), /boot/*/initramfs (regenerate), /boot/limine.conf (regenerate)
      *Rollback:* remove hook + file, re-run limine-mkinitcpio-install, keep /tmp/initramfs.rc.bak

- [x] **5. Reboot** — done by user ✅ — override loaded (`Table Upgrade: override [SSDT-Rtd3-I2C_DEVT]`), client now `i2c-BMI0260:00`, bound to bmi270 at boot with **no NAK** (retry not needed)
      *Dependencies:* step 4
      *Rollback:* boot menu → previous kernel (LTS) still boots

- [x] **6. Verify** — ✅ `iio:device0` name=`bmi260`; accel |g|=9.84 m/s² at rest; gyro ~0; temp + step channels present

- [x] **7. Boot-time retry** — ❌ **not needed** (driver bound cleanly at boot; no NAK)

- [ ] **8. Optional: auto-rotation** — install `iio-sensor-proxy`; add `ACCEL_MOUNT_MATRIX` via udev hwdb once physical orientation is determined
      *Dependencies:* step 6 (optional)
      *Rollback:* remove hwdb entry

## Risks

- DSDT override is lost if firmware tables change (rare) — redo steps 2–4.
- If the initrd rebuild fails, the old initramfs from before the edit is regenerated by rollback (step 4).
- The kernel `acpi_override` initrd path must match (`kernel/firmware/acpi/`); verify with kernel strings before finalizing step 4.
